# 4. 비용 계산과 운영 루틴

## 4-1. 시나리오별 월 비용 (월 55시간 기준)

단가는 RunPod 공식 요금표 기준입니다(2026-10 조회). 환율은 **1달러 = 1,400원으로 가정**했으니 실제 환율로 다시 곱해 보세요.

| | A. Community + 매번 terminate **(권장)** | B. Community + 볼륨 디스크 + stop | C. Secure + 네트워크 볼륨 |
|---|---|---|---|
| GPU | $0.34 × 55h = $18.70 | $18.70 | $0.74 × 55h = $40.70 |
| 부팅 오버헤드 | 22회 × 약 12분 ≈ 4.4h → **$1.50** (추정) | 회당 짧음 ≈ $0.50 | ≈ $0.50 |
| 스토리지 | 컨테이너 60GB, 실행 중에만 과금 ≈ $0.49 | 볼륨 30GB: 실행 중 $0.10 + **정지 중 $0.20/GB/월** ≈ $5.80 | 네트워크 볼륨 50GB × $0.07 = $3.50 |
| **합계** | **≈ $20.7 ≈ 2.9만 원** | ≈ $25 ≈ 3.5만 원 | ≈ $45 ≈ 6.3만 원 |
| 단점 | 매번 이미지 pull·셰이더 컴파일 | stop 후 재시작 때 그 호스트 GPU가 이미 대여 중이면 못 씀(Community 특성) | 예산 초과 |

**왜 A인가**
- 예산(월 3만 원) 안에 들어오는 건 A뿐입니다.
- B는 "정지 중에도 GB당 $0.20"이 핵심 비용입니다. 정지 시간이 사용 시간보다 훨씬 길어서 저장 비용이 커집니다.
- 네트워크 볼륨은 Secure Cloud 전용이라 Community에서는 고를 수 없습니다.

**부팅 오버헤드는 추정치입니다.** 이미지 pull 시간이 과금되는지는 공식 문서에서 확인하지 못했습니다. 첫 3회 정도는 아래 루틴에 따라 **Deploy를 누른 시각부터 noVNC에 접속한 시각까지 실측**해 기록하세요. 오버헤드가 회당 20분을 넘으면 B를 다시 검토할 만합니다.

### 더 싸게: GPU 등급 실험 (환경이 안정된 뒤 한 번)

| GPU (Community) | $/hr | 55h 비용 | 비고 |
|---|---|---|---|
| RTX 4090 | 0.34 | $18.7 | 기준 |
| RTX 3090 (24GB) | 0.22 | $12.1 | RT 코어 있음 |
| RTX A5000 (24GB) | 0.16 | $8.8 | RT 코어 있음 |

Isaac Sim 6.x 공식 요구사항 표의 최소 사양 예시는 RTX 4080이고, RT 코어가 없는 GPU(A100/H100)만 명시적으로 미지원입니다. 3090/A5000은 **공식 표에 없어서 동작 여부를 확인하지 못했습니다.** 4090에서 03 실습이 된 다음, 같은 이미지로 30분만 띄워 `isaac-diag`와 실습 씬 FPS를 비교해 보세요(비용 약 $0.1). 된다면 월 비용이 절반 이하로 내려갑니다. 이때도 CUDA 13.2+ 필터는 똑같이 겁니다.

## 4-2. 세션 루틴

### 켜기 전 (PC, 무료)
- 오늘 할 실습 목표 한 줄과 필요한 스크립트를 PC에서 미리 작성합니다. **pod 안에서 문서를 읽거나 고민하는 시간이 가장 비싼 시간입니다.**
- RunPod 잔액을 확인합니다. **자동 충전은 끄고 잔액을 $10~20만 유지하세요.** 사고가 나도 손실 상한이 잔액으로 묶입니다. 잔액이 $0이 되면 RunPod이 pod를 자동 정지합니다.

### 시작 (목표 10분 이내)
1. Deploy: Community, 4090, CUDA 13.2+, RAM 32GB+, 템플릿 선택(02 문서)
2. Logs 탭에서 진단 결과를 확인합니다. **FAIL이면 즉시 terminate하고 재배포합니다.** 고쳐 보려 하지 않습니다.
3. PC에서 작업 파일을 올립니다(공인 IP·SSH가 되는 호스트일 때).
   ```bash
   scp -P <PORT> -i ~/.ssh/runpod_ed25519 -r ./work root@<IP>:/root/
   ```
   `scp -r`로 PC의 `work` 폴더를 pod의 `/root/work`로 복사합니다. 포트 옵션은 ssh와 달리 **대문자 `-P`**입니다.

### 작업 중
- 결과물은 `/root/work`에만 저장합니다. 다른 경로는 terminate하면 사라집니다.
- `MAX_SESSION_HOURS=3` 타이머가 돌고 있습니다. 10분 전 경고 창이 뜨면 바로 마무리하세요.

### 끝내기 (5분)
1. Isaac에서 **File → Save** (`/root/work/*.usd`)
2. 작업물을 PC로 회수합니다.
   ```bash
   scp -P <PORT> -i ~/.ssh/runpod_ed25519 -r root@<IP>:/root/work ./
   ```
   방향만 반대입니다. PC 쪽 git 저장소에서 커밋하면 **pod 안에 GitHub 토큰을 둘 필요가 없습니다.**
3. 콘솔에서 pod를 **Terminate**합니다(Stop 아님).
4. **Pods 목록이 비어 있는지**와 Billing에서 시간당 지출이 0인지 확인합니다.

> 공인 IP가 없는 호스트라 scp가 안 되면: 작은 텍스트는 noVNC Clipboard로 옮기고, 그래도 부족하면 접근 범위를 저장소 하나로 제한한 **GitHub fine-grained token**을 RunPod Secret으로 넣어 pod에서 직접 push합니다. 토큰은 만료일을 짧게 잡으세요.

### 주 1회
- Billing 내역에서 예상 밖 항목(남은 pod, 볼륨)을 점검합니다.
- 이미지를 고쳤다면 태그를 올리고(`-v2`) 템플릿 이미지도 바꿉니다.

## 4-3. 에셋·캐시 다운로드 줄이기

Isaac Sim 6.x의 로봇·환경 에셋은 기본적으로 **NVIDIA 클라우드에서 그때그때 받아** pod 안에 캐시합니다. terminate 운영에서는 이 캐시가 매번 사라집니다. 돈보다 **시간**이 드는 문제인데, 그 시간도 결국 GPU 과금이라 줄일 가치가 있습니다.

- **씬을 작게 유지하세요.** Ground Plane + 로봇 1대 + 큐브 몇 개로 충분합니다. warehouse 같은 대형 환경은 수백 MB~GB를 받고 VRAM도 많이 씁니다.
- **에셋 브라우저를 구경하듯 넘기지 마세요.** 썸네일과 프리뷰도 다운로드입니다. 쓸 에셋은 정해서 검색하세요.
- **같은 로봇을 계속 쓰세요.** 저장한 `lab01.usd`를 다음 세션에 열면 같은 에셋만 다시 받습니다.
- **셰이더 캐시**: 첫 실행 셰이더 컴파일(수 분)이 매 세션 반복됩니다. 실측 오버헤드가 크면 B 시나리오로 바꾸면 됩니다. `start.sh`는 `/workspace`가 실제 볼륨이면 캐시를 자동으로 그쪽에 연결합니다.
- **이미지 크기**: ROS가 필요 없는 세션이면 `INSTALL_ROS=0` 이미지로 pull 시간을 줄일 수 있습니다. 다만 템플릿을 두 개 관리해야 하니, 초반에는 하나로 가는 게 편합니다.
